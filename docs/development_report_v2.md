作成日: 2026-03-02

## 1. システム概要

東証全銘柄（プライム・スタンダード・グロース、約3,700〜3,900銘柄）を対象に、
翌営業日の株価をAIで予測し、デイトレード向け銘柄を毎日推薦するシステム。

| 項目 | 内容 |
|------|------|
| 元手 | 200万円 |
| 取引スタイル | 前場始値取得 → 後場終値決済（当日精算） |
| モデル | LightGBM（全銘柄共通モデル） |
| 特徴量 | テクニカル指標 + マクロ指標 + 米国市場 + 外資動向 |
| 推薦数 | 上位20銘柄 |

## 3. 試行詳細

### 試行#1〜2: ベースラインと最初の失敗

**ベースライン構成:**
- ターゲット: 翌日終値の絶対リターン（前日終値比）
- 始値RMSE が 58,566 という異常値 → 始値モデルの学習が機能していなかった

**試行#2 の崩壊:**
```
model_open  ターゲット: target_open_return（市場込み）
model_close ターゲット: close_return - 市場リターン（市場除き）
→ expected_gain = pred_close - pred_open の意味が失われ推薦勝率29.6%に崩壊
```

**教訓**: 始値/終値モデルのターゲット定義を一貫させる必要がある。

---

### 試行#3〜5: 日中騰落率モードと特徴量拡張

**日中騰落率モード (`USE_INTRADAY_TARGET=True`):**
```
model_open  : target_open_return（前日終値→翌日始値）  ← 変更なし
model_close : target_intraday_return（翌日始値→翌日終値）  ← 変更
expected_gain = predicted_intraday_return
```
- 定義の整合が取れた
- 始値RMSEの異常値は残存（後のPhase Aで解消）

**追加した特徴量:**

| カテゴリ | 特徴量 | 効果 |
|--------|-------|------|
| 米国市場 | S&P500リターン, NASDAQ, VIX変化率, USD/JPY水準・変化率 | gain上位に入る主要特徴量 |
| 外資動向 | 外資売買差引（週次） | 需給シグナル |
| ギャップ | gap_ratio（寄付ギャップ比率）, gap_abs, gap_vs_atr | 始値予測に有効 |
| マクロ | 日経先物リターン | 夜間の市場方向を反映 |

**重要な知見（特徴量重要度分析）:**

| 特徴量 | gain（始値モデル） | 解釈 |
|--------|----------------|------|
| `beta_20d` | 18.9% | 市場感応度（最重要） |
| `vix_change` | 9.8% | リスクオン/オフ |
| `mkt_return_1d` | 9.0% | 市場方向 |
| `nasdaq_ret` | 7.9% | 米国ハイテク |
| `usdjpy_level` | 7.8% | 円安/円高 |
| `amihud` | 5.0% | 非流動性（価格インパクト） |

→ 始値予測は**マクロ・米国市場指標が支配的**。個別テクニカル指標の寄与は小さい。

**Optuna多目的最適化 (試行#5):**
- 目的関数: rmse_open, rmse_close, 1-dir_acc_open, 1-dir_acc_close（4目的最小化）
- サンプラー: NSGAIISampler（進化的多目的最適化）
- パレートフロントから推薦パラメータを自動選択

### 試行#6: Sharpe 1.62達成（ターニングポイント）

**変更内容:**
1. Optunaで探索した最適パラメータを適用
   ```
   learning_rate: 0.047, num_leaves: 248, max_depth: 11,
   min_child_samples: 22, feature_fraction: 0.51, bagging_fraction: 0.58
   ```
2. ギャップ特徴量を追加（gap_ratio, gap_abs, gap_vs_atr）

**結果:**
```
始値_方向的中率: 41.4%
日中騰落率_方向的中率: 55.4%
Sharpe_Ratio: 1.618
最大ドローダウン: -1.651
```

→ 方向的中率55%を突破。実用レベルの閾値に到達。

### 試行#7〜9: ベータ依存性の排除（Phase A/B）

**問題の本質（試行#7以前）:**
```
市場上昇日: ほぼ全銘柄が上昇 → 推薦勝率 75〜85%
市場下落日: ほぼ全銘柄が下落 → 推薦勝率  5〜15%
→ 最大 80pp の乖離（モデルが個別銘柄の固有の動きではなく市場全体を予測していた）
```

**Phase A: 日中αターゲット化 (`USE_INTRADAY_ALPHA=True`):**
```python
target_intraday_alpha = intraday_return - mkt_intraday_return
# 「市場全体の動きを上回るか」を直接予測
```

結果:
- 始値RMSE: 58,592 → **0.017 に正常化**（長年の異常値がようやく解消）
- Sharpe: 1.77〜2.53（改善）
- 日中α方向的中率: 51.8〜52.4%

**Phase B: 2値分類モデル化 (`USE_BINARY_CLOSE=True`):**
```python
y_close = (target_intraday_alpha > 0).astype(int)
params["objective"] = "binary"
params["metric"]    = "binary_logloss"
# 「市場を上回るか否か」を直接分類
```

結果:
- Sharpe: **2.40〜3.06**（さらに改善）
- AUC: 0.559
- 方向的中率: 53.1〜53.8%

**3年データの実験（試行#8）:**
- 結果: 方向的中率 42.8% → 悪化
- 原因: 2022年金利上昇・2023年回復・2024年上昇など異なる市場レジームが混在
- 結論: 1年データ（250日）が最適

---

### 試行#10〜11: 市場動向との統合（Phase C/D）

**Phase C: 市場方向予測モデル (`USE_MARKET_MODEL=True`):**
- 別モデルで翌日市場全体の上昇/下落確率を予測
- `market_up_prob` を算出し、推薦フィルタの閾値を動的調整
- **問題**: 市場下落確率 > 0.45 のとき閾値を15%に引き上げ → **推薦ゼロ**になる

**Phase D: Claude CLI センチメント分析 (`USE_LLM_SENTIMENT=True`):**
- yfinanceからマクロティッカーのニュースヘッドラインを収集
- Claude CLIに渡して市場センチメントスコア（-1〜+1）とリスク銘柄を取得
- `market_up_prob` に合成（重み: LLMセンチメント × 確信度 × 0.5）
- LLMが指定したリスク銘柄を推薦から除外（2026-03-02時点で8銘柄除外）

---

### 試行#12: 5段階レーティング導入（2026-03-02）

**解決した問題:**
- 弱気相場で推薦ゼロになる問題（Phase C の閾値引き上げロジックを廃止）

**新設計:**
```
LGBM推薦: 固定閾値（expected_gain_pct > 0）で常に銘柄を出力
市場動向: 各銘柄に★1〜5 のレーティングとして表現
```

**レーティング算出:**
```python
individual_rank = expected_gain_pct.rank(pct=True)  # 推薦候補内パーセンタイル
composite = market_up_prob * 0.5 + individual_rank * 0.5
# composite → ★1(< 0.25) / ★2(< 0.40) / ★3(< 0.60) / ★4(< 0.75) / ★5(≥ 0.75)
```

**同時修正:**
- バイナリモードで `pred_close = 0.6`（確率値）が円建て価格として誤表示されていたバグを修正
  → `pred_close` を `NaN`、`close_up_prob`（確率列）を別途追加

## 4. 現在のシステム構成

### モデル設定（2026-03-02時点）

```python
USE_INTRADAY_TARGET  = True   # 日中騰落率ターゲット
USE_INTRADAY_ALPHA   = True   # αターゲット（市場超過リターン）
USE_BINARY_CLOSE     = True   # 2値分類モード
USE_MARKET_MODEL     = True   # 市場方向予測モデル
USE_LLM_SENTIMENT    = True   # Claude CLIセンチメント分析
LLM_SENTIMENT_WEIGHT = 0.5    # LLM重み（× 確信度）
MARKET_RATING_MARKET_WEIGHT = 0.5  # レーティング市場動向重み
```

### データフロー

```
[引け後 15:30〜]
  1. 東証銘柄コード取得（~3,900銘柄）
  2. Yahoo Finance から1年分OHLCV取得
  3. 外資売買動向・米国市場データ取得
  4. 特徴量エンジニアリング（テクニカル指標 + マクロ指標）
  4a. Optunaハイパーパラメータ最適化（任意）
  4b. 最適化済みパラメータ適用（任意）
  4c. 市場方向予測モデル学習 → market_up_prob 算出
  4d. Claude CLI センチメント分析 → LLM合成 market_up_prob
  5. LightGBM で翌日始値・終値（確率）予測
  6. バックテスト評価（任意）
  7. 単元株数取得
  8. 推薦銘柄生成 + ★レーティング付与
  9. CSV / Markdown 出力
```

## 6. 残課題・今後の方針

### 高優先度

| 課題 | 現状 | 対策案 |
|------|------|--------|
| 市場下落日の勝率低さ | 測定中（αモードで改善見込み） | Phase C/Dのレーティングで可視化済み。実績を積んで評価 |
| 始値RMSE の解釈 | αモードで0.017（正常） | ウォークフォワード検証での継続モニタリング |
| LLMセンチメントの精度 | 定性評価のみ | 予測との相関を事後検証 |

### 中優先度

| 課題 | 対策案 |
|------|--------|
| テクニカル指標の冗長性 | 重要度下位特徴量を削除し過学習抑制 |
| time-decay weighting | 直近データへの重みづけ（direct recent data bias） |
| 外資動向データ（週次） | 日次データへの切り替えを検討 |

### 実験候補

| アイデア | 期待効果 | コスト |
|---------|---------|--------|
| iTransformer（時系列Transformer） | 多変量時系列の銘柄間相関を学習 | 高 |
| Chronos / TimesFM | 少データ銘柄の汎化 | 高 |
| セクター別個別モデル | セクター固有パターンの学習 | 中 |
| 信用倍率・空売り比率 | 需給の先行指標 | 高（データ取得） |

## 7. 技術的知見

### やってみてわかったこと

1. **始値予測はマクロ指標が全て**: beta_20d・VIX・USD/JPY・米国市場の4指標だけで始値の動きのほとんどが説明できる。個別テクニカル指標の寄与は小さい。

2. **ターゲット定義の整合性は最重要**: 試行#2の失敗が示す通り、始値モデルと終値モデルのターゲットが「同じ基準（市場込みか市場除きか）」で定義されていないと推薦スコアが崩壊する。

3. **1年データが最適**: 3年データは市場レジームのミックスで悪化。直近250日が最良のトレードオフ。

4. **分類 > 回帰（終値モデル）**: 「いくら上がるか」より「市場を上回るか否か」を直接分類する方がSharpe・安定性ともに優れる。

5. **αターゲット化で始値RMSE正常化**: 始値RMSEの異常値（58,566）は、αモード適用後に0.017まで正常化。原因は絶対リターンターゲットのときに大きなスケール差があったため。

6. **閾値フィルターより情報提示の方が有用**: Phase Cの「弱気相場で閾値を上げる」設計は推薦ゼロを引き起こした。代わりに「★レーティングとして表示してトレーダーが判断」する設計の方が実用的。
